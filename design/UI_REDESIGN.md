# 界面重设计：苹果风格 + “寻寻”（2026-10）

桌面客户端（Tauri 2 + WebView2）的整套界面换成统一的苹果风格，并加入六个交互。界面仍是手写的原生 JS/CSS，没有构建步骤；新增的库为零，全部在 `project/ui/static/` 下。

原型确认后用户加了两条：说明文字太多要精简、突出层次；步骤文案太死板，并把产品改成一只帮你查资料的小宠物。于是有了第 7、8 节。

## 1. 现状审计：为什么显得乱

审计截图（浅色、1280 宽）存放在会话笔记目录 `ui-redesign-shots/before/`。

| 问题 | 例子 |
|---|---|
| 盒子套盒子 | 设置页：白色面板 → 带边框的输入框 → 再带边框的单选卡片；每层都有 1px 边框和白底，层级全靠边框区分 |
| 圆角没有规律 | 6、7、8、9、10、11、12、14、18、999 px 混用 |
| 字号、字重太多 | 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 15.5 px，字重 450–700 共 9 档 |
| 控件是浏览器默认样式 | 原生复选框、单选框、下拉框（问答模型）、`<details>` 三角 |
| 两套文件图标 | 知识库里是彩色方块 + 扩展名，找文件结果里是折角文档 |
| 颜色偏饱和且不统一 | 靛蓝强调色 #3d5af1 + 暖灰底色；状态徽章 5 种颜色；选中的单选卡片整块填蓝 |
| 等宽字体到处都是 | 知识库路径、监控目录全用等宽字体，和中文混排很突兀 |
| 说明文字堆成墙 | 设置页每个选项下都有两三行灰字，三个选项的说明同时出现 |
| 几乎没有动效 | 视图切换、展开收起、状态变化都是瞬间跳变；只有阅读面板滑入 |
| 文件列表是平铺的 | 123 个文件不分文件夹，同名文件（如两份“01 申报书.pdf”）无法区分 |

## 2. 设计令牌

全部定义在 `app.css` 顶部的 `:root`，深色值在 `@media (prefers-color-scheme: dark)` 和 `:root[data-theme="dark"]` 里各写一遍（跟随系统 + 手动切换）。

### 字体
- 正文：`"Segoe UI Variable Text", "Segoe UI Variable", "Segoe UI", -apple-system, "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", system-ui`。Windows 上拉丁字母用 Segoe UI Variable，中文落到微软雅黑 UI。不打包 SF Pro（授权不允许非苹果平台）。
- 大标题：同一字族的 Display 光学尺寸。
- 等宽：`"Cascadia Mono", "SF Mono", Consolas`，只用于 Key、模型 ID 和代码。
- 字号六档：12（说明）/ 13（脚注）/ 15（正文）/ 17（小节标题）/ 22 / 30（大标题）。界面控件文字 13.5–14。字重四档：400 / 500 / 600 / 700。

### 颜色
| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | #FFFFFF | #1B1B1D | 对话区 |
| `--bg-grouped` | #F5F5F7 | #141416 | 知识库、设置的底色 |
| `--surface` | #FFFFFF | #232326 | 分组列表、卡片 |
| `--label` / `-2` / `-3` / `-4` | #1D1D1F / #424245 / #6E6E73 / #A1A1A6 | #F5F5F7 / #D1D1D6 / #98989F / #636368 | 四级文字（第 4 级只用于占位符和装饰图标） |
| `--sep` | rgba(60,60,67,.13) | rgba(255,255,255,.09) | 发丝分隔线 |
| `--fill` / `-2` / `-3` | systemFill 三档 | 同左（更高透明度） | 按钮、分段控件、输入框底 |
| `--accent` | #007AFF | #0A84FF | 系统蓝：主按钮、选中、开关以外的强调 |
| `--accent-text` | #0066CC | #4AA3FF | 白底上的蓝色文字（对比度 ≥ 4.5） |
| `--green` / `--orange` / `--red` | iOS 系统色 | 深色版系统色 | 只表示状态（通过、警告、失败），各带 `-text` 与 `-soft` |

磨砂表面：`--glass`（72%）与 `--glass-strong`（88%）配合 `backdrop-filter: saturate(180%) blur(24–28px)`，用在侧栏、浮动输入框、页面工具栏、弹出菜单、提示、操作栏、对话框、阅读面板标题栏。

### 形状、阴影、间距
- 圆角：6（徽标、kbd）/ 8（按钮、列表行）/ 10（输入框）/ 14（分组列表、卡片）/ 18–22（建议卡片、输入框外框）/ 胶囊。支持 `corner-shape` 的内核上卡片类元素改为连续曲率圆角（superellipse）。
- 阴影三档：`--shadow-1` 贴面（列表、来源卡片）、`--shadow-2` 浮起（建议卡片、输入框）、`--shadow-3` 悬浮（菜单、对话框、阅读面板）。深色模式阴影更重并加 0.5px 亮边。
- 边框只在必要处出现：分组列表靠底色和阴影区分，行之间是缩进的发丝线（iOS 分组列表）。
- 间距 4 的倍数：4 / 8 / 12 / 16 / 20 / 24 / 32。阅读栏宽 760，页面栏宽 860。

### 动效
- `--ease-out: cubic-bezier(.22,1,.36,1)`：淡入、滑入。
- `--spring`：阻尼比 0.78 的弹簧采样成 `linear()`，过冲 2%，用于移动类动画（分段控件滑块、开关、叠卡、侧栏抽屉、提示）。
- `--spring-bouncy`：阻尼比 0.5，过冲 16%，只用于“完成”对勾和复选框的勾。
- 时长：140（悬停）/ 240（一般）/ 420（较大的移动）/ 560（弹簧）ms。
- 只动 `transform` 和 `opacity`；例外是叠卡容器的高度（一个元素，避免下方内容跳动）。
- `prefers-reduced-motion: reduce`：所有过渡和动画缩为 1 ms，惯性滚轮直接跳到目标，圆形扩散和视图过渡不播放，转圈指示保留但放慢。

## 3. 组件

- **侧栏**：磨砂源列表。两个导航（问答 / 知识库；已在问答页时再点“问答”开始新对话，像 iOS 重点当前标签回到根页）→ 最近对话 → 底部状态点与设置齿轮。正在回答的对话显示三个跳动的蓝点，可同时有多个。
- **按钮**：主按钮（系统蓝）、次按钮（灰色填充）、文字按钮（蓝字）、危险（红字）、图标按钮。按下缩放 0.97。
- **开关**：iOS 开关（真实的 `<input type="checkbox" role="switch">`），按住时滑块变宽。
- **分段控件**：真实单选框，等宽分段 + 一个滑动的白色滑块。用于回答模式、推荐依据、图片理解、外观、文件状态筛选、阅读面板的原文 / 解析文本。选项的说明只显示当前选中的那一条。
- **分组列表**：设置和知识库的主体，行 = 左侧图标（可选）+ 标题与一行说明 + 右侧控件。
- **大标题**：知识库、设置顶部 30px 大标题；滚到工具栏下方后，磨砂工具栏中间淡入小标题。
- **图标**：`icons.js` 里一套手绘 SVG（24 网格、1.7px 圆头线），注入成雪碧图，`Icons.svg("trash")` 引用。主窗口和快速搜索窗口共用。
- **对话框**：`UI.confirmSheet` 替换 `confirm()`，苹果警告框样式，Esc 取消，危险操作默认焦点在“取消”。

## 4. 六个交互放在哪里

| # | 交互 | 位置 | 做的事 |
|---|---|---|---|
| 1 | 完成反馈按钮 `UI.runDone` | 添加文件夹、保存 / 测试 API Key、复制回答、重新扫描、批量重新入库、保存敏感词、保存快捷键、刷新 | 文字 → 转圈 → 描出的对勾（轻微回弹），按钮变绿；失败时变红并左右抖动，错误原因用提示说明 |
| 2 | 勾选联动 `UI.Selection` | 知识库文件列表 | 文件按所在文件夹分组；文件夹复选框三态（全选 / 部分 / 无），数量实时滚动；选中后底部浮出磨砂操作栏：只在这些文件里提问（设置 `scope_doc_ids`）、重新入库、移除 |
| 3 | 叠卡展开 `UI.Deck` | 回答下的引用来源；找文件结果里同名文件 | 多个来源叠成一摞（最多露出三张，右侧 +N），点按后弹簧展开成网格；悬停正文里的引用 [n] 时，第 n 张卡从牌堆里升到最上面。找文件结果里同名不同位置的文件叠成一行，点“N 个位置”展开 |
| 4 | 吸附卡 + 画线 `UI.SnapRail` / `UI.connect` | 首页“猜你想问”；回答里的引用 | 推荐问题是横向吸附滚动的卡片行，下方一条线随滚动、悬停、键盘焦点画到当前卡片；悬停引用 [n] 时从引用画一条曲线连到第 n 张来源卡 |
| 5 | 惯性滚轮 `UI.Wheel` | 设置 → 问答模型；找文件结果的“修改时间”（全部 / 今天 / 7 天 / 30 天） | 3D 滚筒，鼠标滚轮按格、触控板跟手、拖动带惯性和边缘阻尼，弹簧吸附；方向键 / PageUp / Home / End；`role="listbox"` + `aria-activedescendant`。停稳后才生效。页面滚动途经滚轮时不被截走 |
| 6 | 圆形扩散转场 `UI.circleTransition` / `UI.revealFrom` | 主题切换、新对话、“只在这些文件里提问”跳回对话；打开阅读面板 | View Transitions API，新画面从点按位置以圆形扩开；不支持时直接切换。阅读面板单独用 `clip-path` 圆形从被点的卡片处展开 |

## 5. 不变的东西

- 流式回答每帧最多重绘一次（`scheduleDraftPaint`），多个对话可同时回答，切走的对话在后台继续。
- 引用编号（`citations.js`）、追问（`followups.js`）、首页推荐、找文件行（`filerow.js`）、原文预览（`preview.js` 与 vendor 下的 PDF.js、docx-preview、JSZip、SheetJS）的逻辑不改，只改样式和外层结构。
- 不加任何 CDN 资源，Tauri CSP 不变。

## 6. 新增的纯逻辑与测试

`project/tests/js/ui.test.cjs`：滚轮吸附与惯性投射、边缘阻尼、弹簧收敛、鼠标滚轮按格、三态选择、叠卡顺序、同名文件分组。由 `tests/test_ui_kit.py` 在 pytest 里调用 `node --test`。

后端为界面补了两个小接口：
- `POST /api/v1/files/{id}/reindex`：批量“重新入库”。`LibraryService.reindex` 标记强制重读（内容没变也重新解析），原文件丢失或离线时原样返回。测试在 `tests/test_file_library.py`。
- `POST /api/v1/settings/test-key`：设置页“测试”。用输入框里的 Key（留空则用已保存的）请求硅基流动的模型列表，Key 无效、网络不通分别给出原因，并说明当前问答模型能不能用。测试在 `tests/test_key_check.py`。

## 7. 名字和角色：寻寻

- **名字**：寻寻，一只金毛寻回犬（寻回犬即 retriever，正好对应 RAG 里的“检索”）。口头禅是“叼回来”：它去你的资料里把答案叼回来。
- **形象**：`icons.js` 的 `Icons.mascot()`，暖金色小狗头像，浅杏色圆角底。平时每隔几秒眨一次眼；工作时（流式回答、快速搜索查询中）左右嗅、耳朵摆动；首页头像悬停会跳一下。减少动态效果时都不动。
- **出现的地方**：侧栏品牌、首页问候旁、每条回答的步骤标题（“寻寻正在翻资料…” / “寻寻跑了 5 步 · 7.2 秒”）、空的知识库、找不到文件、快速搜索窗口、启动画面、窗口标题和应用图标（`desktop/src-tauri/icons/*` 由 1024px 渲染图经 `tauri icon` 生成）。
- **没改的**：安装包的 `productName`（“企业知识库”）和 `identifier` 保持不变，这样新版本覆盖安装旧版本、数据目录也不变；要彻底改名需要单独处理升级迁移。
- **语气**：只用在步骤、空状态、进度这些“它在干活”的地方；错误提示、隐私警告、确认框保持直白，不卖萌。

### 步骤文案不再写死

`describeStep(ev, seed)` 用每一步事件里的真实数据拼句子（检索词、叼回几段、找到几个文件、核对是否通过），同一类步骤有两三种说法，按回答 id 固定选一种（重绘不会变来变去）。技术名称（混合检索、RRF、父块……）放进悬停提示。例：

| 节点 | 以前 | 现在 |
|---|---|---|
| analyze_query | 理解问题 · 文档问答　检索词 … | 听懂了：去资料里找答案　要找 … |
| retrieve | 混合检索　Dense + BM25 → RRF → Rerank，保留 6 个片段 | 翻遍资料，叼回 6 段相关内容 |
| rewrite_search | 相关性不足，改写查询 | 这些不太对路，换个说法再找 |
| build_context | 还原父块，构建上下文 | 把前后文一起叼过来读一读 |
| fact_check | 事实校验通过 | 逐句对照原文，没问题 |
| refuse | 证据不足，拒绝回答 | 资料里没找到可靠的依据，不乱说 |

## 8. 精简文字

原则：每行一个标题，最多再加一行短说明；只给做决定需要的信息；同一处只说一次。
- 设置页：去掉所有分组脚注；开关行只留标题（隐私相关的“会发给模型服务”保留为一行橙字）；分段控件下只显示当前选项的一句话；敏感词、排除文件夹、不再推荐的文件收进可展开的行，行尾显示数量；“回答模式”改叫“核对方式”。
- 知识库：副标题一句话；去掉格式说明和“导入单个文件”的长括号；文件行不再重复整条路径（分组标题已经是文件夹），改为修改时间。
- 对话：输入框下的提示行删掉；状态标签缩短（“已对照原文”“出处已核对”“没核对完，请点开出处看看”）；找文件结果去掉耗时标签。

## 9. 侧栏状态行、悬浮设置、打开文件（第二轮，2026-10-28）

用户反馈：主页面布局有点乱，设置放到下方，“服务就绪”那块精简；设置用悬浮窗口，不完全盖住问答和知识库；打开文件时的“用本机 Word 转换为 PDF”不需要让用户知道，改成寻寻找文件的动效。

**侧栏底部只剩一行**：状态点 + 齿轮。
- 一切正常：一个绿点，没有字（悬停提示“一切就绪 · 当前模型”）。
- 正在读文件：蓝点呼吸 +“正在读 12 个文件”+ 细进度条，点一下去知识库。库页没打开时每 15 秒（忙时 3 秒）问一次 `/library/status`。
- 出问题：红点 + 一句原因，点一下到设置里对应的地方。优先级：后台没有响应 > 还没有 Key > 服务未就绪 > 模型连接失败（一次回答因模型服务中断，下一次成功回答或测试 Key 通过后消失）。
- 判断逻辑在 `status.js` 的 `AppStatus.describe`，有 Node 测试。

**设置是一张悬浮面板**：和阅读面板同一种右侧卡片，560 px 宽；背后的页面变暗、轻微模糊但仍可见，流式回答不受影响；点外面或按 Esc 关闭（设置在阅读面板之上，Esc 先关它）；改动立即生效，没有“保存全部”。顶部分段控件切换五组：模型与密钥 / 推荐与追问 / 图片识别 / 快捷键（只在桌面版出现）/ 关于（主题、数据位置、服务状态、版本）。“图片识别”一组整块是 `<section data-pane="image">`，方便另一条线替换。侧栏不再有“设置”导航项和主题按钮。

**打开文件不提 Word、PDF、转换**：
- 所有格式加载时都是同一个寻寻动画：小狗嗅、一串脚印、按等待时长换的一句话（寻寻找到文件踪迹 → 正在把文件叼回来 → 快到了，再等一下），下面一张骨架纸。原来“由本机 Word 转换为 PDF 显示 · 本次转换 N 秒”这类说明都去掉了；.doc 打不开时只说“暂时无法在软件内显示这个文件”。
- 少等：后端 `PreviewPrefetcher`（`library/preview.py`）一个后台线程逐个转换，正在打开的文件插队；回答里的来源卡片、找文件结果、快速搜索的前三个结果出现时就把其中的 Word 文件交给它（`POST /api/v1/documents/prepare`，前端 `AppStatus.PrepareQueue` 去重、合批）；应用空闲 2 分钟后，顺带转换最近 14 天新加入的 Word 文件，每轮最多 3 个；后台失败过的（包括超时）不在后台重试，用户打开时再试。
- 打开 .docx 时 `GET /documents/{id}/pdf?wait=1.5` 最多等 1.5 秒：没好就返回 202，阅读面板立刻用网页排版显示，转换在后台继续，下次打开直接用缓存（实测 17 ms）。.doc 没有别的显示方式，照旧等待。

## 10. 主页（第三轮，2026-11）

用户反馈：主页面有一点混乱，要能吸引人，还比较简约。

**之前的问题**：问候在左上角，输入框远在下方，中间一排控件；第一张卡有亮蓝描边，每张卡三行字；说明图标孤零零地在右上角；占位符是一条随机问题；“问答”标题重复了一遍。

**现在只有一个焦点**：一行大字问候、一行短句、一个输入框，寻寻趴在输入框上沿，只露出半个身子。试过两个方向：A 是寻寻单独站在标题上方，B 是寻寻趴在输入框上。选了 B：小狗和输入框读起来是一个东西，也更紧凑，放在右侧不挤标题。

- **输入框还是同一个元素**：`#composer` 一直固定在问答页底部，主页上用 `translateY` 抬到预留的 `#homeSlot` 上（`placeComposer`）；第一次提问时撤掉位移，带弹性滑回底部，寻寻同时缩回去，主页内容淡出（`fadeOutHome`）。范围选择、焦点、追问灰字的逻辑都不用改。
- **位置跟着布局走**：输入框、窗口和 `.empty` 的尺寸一变就重新放一次（`ResizeObserver`）。只在切换状态时量一次不够：减少动效时全局规则让所有属性都有 1 ms 过渡，切换的瞬间量到的还是旧的 padding，输入框会压住副标题。
- **三种状态**：`AppStatus.homeMode` 决定。有资料是输入框居中；资料库还是空的，就是寻寻 + 问候 + 添加文件夹 / 添加文件，输入框留在底部；有对话时主页关闭。
- **推荐**：默认一屏三张加半张，只留问题和文件名，“接着上次的话题”这类标签只在有意义时显示（`AppStatus.cardTag`）。去掉蓝色描边。吸附和画线都保留：线改成暖色，末端是一只爪印，滚到头时走到最后一张卡。翻页箭头只在鼠标移上来时出现。
- **推荐说明**：收进“猜你想问”旁的小图标，悬停或键盘聚焦时显示，内容和“推荐设置”链接都没有少。
- **占位符**固定为“问点什么，或者让寻寻帮你找文件…”，不再用随机问题，免得让人觉得软件在翻私人文件。
- **顺手修的**：藏在屏幕外的阅读面板和窄窗口侧栏的阴影会漏到页面边缘，现在收起时没有阴影。
- 侧栏去掉了“帮你翻资料的小狗”这行字；窄窗口下主页顶栏透明、不显示标题。
