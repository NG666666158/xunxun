# 首页“猜你想问”

首页给出 4 个推荐问题，帮助用户想起知识库里有什么、可以问什么。设计的硬性要求是**适度、透明、可控**：推荐不能让人觉得后台一直在读他的隐私。

## 1. 问题池

| 步骤 | 做法 | 代码 |
| --- | --- | --- |
| 本地模板（默认） | 根据文件名判断文档类型（检测报告、商业计划书、会议纪要、新闻稿、申报指南、政策、规格书、简介、协议、表格……），生成整篇文件的问题；从解析出的小节标题生成小节问题；每个文件再写一个“找文件”问题。**不调用模型。** | `project/suggestions/templates.py` |
| AI 生成（可选，默认关闭） | 设置页单独开关。开启后，每个文件调用一次模型，把文件名、目录和开头约 240 字发给模型服务，生成 3～5 个问题。敏感文件不发送。 | `SuggestionService._build_ai` |
| 检索验证 | 每个候选问题都实际检索一次：问答类要求第一条片段来自来源文件；找文件类要求找文件结果的第一个就是来源文件。同一文档的副本或其他格式（`X.docx` / `X.pdf` / `X (1).docx`）算作同一个来源。没通过的问题也保留记录（`verified=0`），但不会被推荐。 | `SuggestionService.verify` |
| 跟随文件库 | 文件重新入库（内容变了）或改名时重建问题；文件被删除时立即删除它的问题（`LibraryService.on_dropped`），每次同步时再核对一遍。原文件丢失但索引还在的文件保留问题，但不推荐。 | `SuggestionService.sync` |

示例：`1.1.5 ReAct 循环` 生成“ReAct 循环是如何工作的？”，`XX 检测报告.pdf` 生成“《XX 检测报告》的检测结论是什么？”，`生产会议纪要_2026年07月13日.docx` 生成“找一下2026年07月13日的生产会议纪要”。

本地表（都在 `knowledge.sqlite3` 里，单独的连接）：

- `suggestion_pool`：问题、来源文件、类型（ask / find）、生成方式（template / ai）、模板名、是否通过验证、展示次数、点击次数、“不感兴趣”标记。
- `suggestion_files`：每个文件的问题是根据哪个版本生成的（sha256、文件名、模板版本、是否因敏感词被排除、是否已用 AI 生成）。
- `suggestion_blocked`：“不再推荐这个文件”。
- `question_log`：用户发出的提问，只保留最近 200 条、90 天内。

## 2. 抽样

每个候选问题的分数由四部分组成，再按分数加权随机抽取（Efraimidis–Spirakis：`key = u^(1/score)`）：

- **新鲜度**：来源文件加入的时间，`exp(-天数/10)`；
- **相似度**：与最近 20 条提问的词重叠（jieba 分词，越近的提问权重越高），**只用于“接着上次”这一张卡片**；
- **新颖度**：展示次数越多越低，刚展示过的再打 0.3 折；
- **反馈**：(点击 + 1) / (展示 + 2)。

卡片组成：

- 冷启动（没有提问记录、也没有任何点击或“不感兴趣”）：2 张“新加入”、1 张“你可能感兴趣”、1 张“找文件”。
- 之后：约一半的次数出 1 张“接着上次的话题”，再加 1 张“新加入”（7 天内加入的文件）、1 张“找文件”，其余是“你可能感兴趣”。某类没有候选时，用“你可能感兴趣”补上。
- 4 张卡片的来源文件互不相同（副本算同一个文件）；同一文件夹已有卡片时，再抽到它的概率降为 0.35 倍。
- 和已经问过的问题几乎一样（相似度 ≥ 0.85）的推荐问题不再出现。

标签措辞保持中性：“新加入”“来自《文件名》”“接着上次的话题”“找文件”。

知识库为空时不显示推荐，改为“先添加一个文件夹”的引导。首次启动时问题池还在后台生成，首页每 5 秒刷新一次，直到凑满 4 张。

“换一批”：当前这批显示出来时就预取下一批（排除当前 4 个），点击后直接替换，不等网络。

## 3. 隐私清单

**记录了什么（只在本机）**

- 用户在输入框发出的提问文本和时间（仅当“同时参考我的提问”开启时；最近 200 条、90 天内，超出自动删除；设置页可一键清除）。
- 推荐卡片的展示次数、点击次数、“不感兴趣”，以及“不再推荐这个文件”。
- 由文件名和章节标题生成的问题，以及它们是否通过检索验证。

**没有记录什么**

- 打开了哪些文件、在阅读面板停留多久、滚动和浏览轨迹、复制了什么。
- 回答内容、引用了哪些文件（对话记录在 `conversations.sqlite3`，推荐不读它）。
- 快速搜索窗口里的搜索词（那是找文件，不是提问）。

**哪些数据会离开本机**

- 默认情况下，推荐功能本身**不向外发送任何数据**：问题由本地模板生成。
- 检索验证会像普通提问一样调用硅基流动的向量和精排接口：发送的是**生成的推荐问题**和候选片段，与入库、问答时发送的内容同类；不发送提问记录。
- 只有开启“用 AI 生成问题”后，才会把每个文件的文件名、目录和开头约 240 字发给模型服务（每个文件一次）。命中敏感词或在排除文件夹里的文件永远不会发送。

**用户能控制什么**

- 首页推荐总开关（关闭后也不再记录提问）。
- 个性化程度：“仅根据知识库内容”（不记录提问）/“同时参考我的提问”（默认）。
- AI 生成开关（默认关闭，开启前弹窗再确认一次）。
- 敏感词表（可编辑，`A&B` 表示同时出现）和排除文件夹。命中的文件不生成推荐问题，但仍可正常检索和问答。
- 每张卡片的“不感兴趣”“不再推荐这个文件”；被屏蔽的文件可在设置页恢复。
- 清除提问记录。

首页右上角的 ⓘ 悬停说明数据来源，并链接到设置页的“首页推荐”。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/suggestions?n=4&exclude=id,id` | 推荐卡片；`library_empty`、`building`、`file_count` |
| POST | `/api/v1/suggestions/events` | `{action: shown｜click｜dismiss, ids: [...]}` |
| POST | `/api/v1/suggestions/blocked` | `{doc_id}`：不再推荐这个文件 |
| DELETE | `/api/v1/suggestions/blocked/{doc_id}` | 恢复推荐 |
| DELETE | `/api/v1/suggestions/history` | 清除提问记录 |
| GET/PUT | `/api/v1/settings` | `suggestions` 分组；`suggestions_enabled`、`suggestions_personalize`、`suggestions_ai`、`suggestions_sensitive_words`、`suggestions_excluded_folders` |

提问在 `/chat` 和 `/chat/stream` 收到时记录（受上面的开关控制）。
