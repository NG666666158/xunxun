# 回答后的追问建议

每次回答结束后，输入框里用灰字给出最可能的下一问，回答下方再放两三个备选。目标是让追问像 Claude 那样“一键继续”，同时守住首页推荐时定下的原则：**适度，不让人觉得后台在读他的隐私**。

## 1. 交互

| 操作 | 效果 |
| --- | --- |
| 回答完成（`final` 之后） | 前端请求 `/followups`；拿到后第一个建议作为输入框的灰色占位文字，右侧显示“Tab 填入 · Enter 发送”；其余最多 3 个作为小标签放在**最后一条回答**下方 |
| Tab 或 → | 把建议填入输入框，可继续编辑；发送时仍带上它的范围（见下） |
| 输入框为空时 Enter | 直接发送灰字建议 |
| Esc | 关闭这条回答的灰字建议（标签保留） |
| 开始打字（含输入法开始组字） | 灰字立即消失；还没回来的请求取消。清空输入框后灰字重新出现（Esc 关掉的除外） |
| 输入法正在组字 | Tab / Enter / Esc / → 都交给输入法，不触发上面的行为（`isComposing`、`keyCode 229`） |
| 点击标签 | 直接发送 |
| 生成回答期间 | 不显示灰字和标签 |
| 切换会话 | 显示该会话自己的建议（建议随回答一起保存在本地会话记录里）；离开时取消该会话还没回来的请求 |

建议可以改变本会话的提问范围：

- **找文件**之后针对某个文件的问题（标签“文件内”），发送时把范围限定到这个文件（复用 `scope_doc_ids`，范围条会显示“仅在文件内提问”）；
- 在文件内**拒答**后的“全库”建议，发送时取消范围限定；灰字写成“在整个知识库中问：…”，因为灰字没法带标签；
- 在单个文件内，“找一下…”和更宽泛的问法也会取消范围：图在单文件范围内不会走找文件。

设置页“回答模式”面板里有开关“回答后推荐追问”，默认开启。关闭后前端不再请求，后端接口也直接返回空；已保存的建议不再显示，Tab 恢复原来的焦点切换。

## 2. 数据从哪来（隐私）

追问只依据**当前对话**和**这次回答已经检索到的内容**：

- 发给模型的：本轮问题、回答摘要（去掉引用标记，约 300 字）、本会话之前问过的问题（最多 5 个，用来去重）、回答引用的片段和检索到但没用上的片段的**文件名和小节标题**、同一文件里相邻小节的**标题**；找文件时是找到的文件名、匹配的小节和一小段匹配片段；拒答时再加上弱相关片段的开头约 60 字。这些内容在回答时已经发给过模型服务（问答、精排），不会有新的数据离开本机。
- 只在本机使用、不发送的：找到文件的目录（用来写本地模板问题）、片段全文（用来检查追问是否在问资料里没有的细节）。
- 不使用：打开过哪些文件、阅读时长、其他会话、首页推荐的提问记录。闲聊之后的建议取自首页推荐的问题池，遵守首页推荐自己的开关和敏感词规则。

## 3. 按场景生成

| 场景 | 判定 | 方向 | 本地模板 |
| --- | --- | --- | --- |
| 普通问答 `answer` | 知识问答，有回答 | 深入、举例、对比、相邻小节 | 被引用小节的后两个、前一个小节标题（“PagedAttention 机制是如何工作的？”）；检索到但没用上的小节；“能再详细讲讲 X 吗？” |
| 文件内提问 `scoped` | 范围是单个文件 | 同一文件里接下来的小节 | 同上，只取这个文件；没有引用时从文件开头的小节开始 |
| 找文件 `files` | 找到了文件 | 针对找到的文件提问（写明《文件名》，设为文件内），或缩小/换条件重新找 | 按文档类型的问题（协议→“约定了哪些合作内容？”）、匹配小节、文件目录里的小节、“主要讲了什么？”；第二个文件一个问题；结果有多种格式时“…，只要 Word 文档” |
| 拒答 `refused` | 证据不足、或没找到文件 | 保留问题的主题换个问法；改为找文件；扩大范围 | “全库”重问（有范围时）；“找一下和 Manus 有关的文件”；“什么是 Manus？”；提到这个主题的弱相关片段的小节 |
| 闲聊 `chat` | 寒暄、工具查询 | — | 首页推荐问题池（不调模型） |
| 无 | 澄清问题、模型服务出错 | 不给建议 | — |

## 4. 生成方式

```
final ─▶ POST /api/v1/followups {thread_id, question, n: 4}
          │  读 LangGraph 里这个会话的状态；question 对不上（会话已经往下走了、后台重启丢了）就返回空
          ├─ 闲聊：问题池
          └─ 其他：一次流式模型调用（max_tokens 200，截止 4 秒，不重试）
                 ├─ 按时完成：全部行
                 ├─ 到截止时：只留已经完整到达的行（fallback=partial），调用在后台跑完、照样记 token
                 └─ 没 Key / 超时没有完整的行 / 出错：本地模板
              过滤 ─▶ 去重 ─▶ 不足 n 个用模板补齐
```

模型默认用设置页选的问答模型（`followup_model` 可另配）。实测硅基流动上各模型的短调用都在 2.5～4 秒，主要是首 token 时间，换小模型并不更快、问题质量更差，所以没有改用便宜模型，而是靠“流式 + 截止时保留已到的行 + 模板兜底”保证 4 秒内一定有结果。

过滤（都在本机，不额外调用模型或检索）：

- **不离题**：问题的内容二元组（去掉“什么、如何、哪些……”这类问句词）至少 1/3 出现在本轮材料里；
- **拒答后不跑题**：必须提到问题的主题词（检索词的第一个词，如“Manus”“推理加速”）；只共享“资金”这类词不算；
- **不追问资料没写的细节**：问“公式、金额、日期、费率……”而回答和片段里都没有这个词的问题排到最后，不会成为灰字建议。

去重：

- 本会话问过的问题（忽略标点、大小写、空格）；
- 换个说法重复刚才的问题：字二元组 Jaccard ≥ 0.6，或去掉问句词后 ≥ 0.9（“KV Cache 是什么” = “什么是 KV Cache”）；
- 建议之间互相重复（≥ 0.7，或去掉问句词后 ≥ 0.85）；
- 例外：“全库”重问和“只要 PDF”本来就重复原问题；针对找到的文件提问和“找一下 X”主题相同但不是同一件事。
