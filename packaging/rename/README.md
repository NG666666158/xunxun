# 改名为“寻寻”

**状态：公开版 1.0.0 起已启用**（`tauri.conf.json` 已并入下面的配置，发布者也改为“寻寻”）。之后所有版本都要带着 `hooks.nsh`，否则还没升级的旧版用户跳版本时会出现两个程序。

## 改什么，不改什么

| 项目 | 现在 | 改名后 | 说明 |
|---|---|---|---|
| `productName`（快捷方式、卸载项、安装包文件名） | 企业知识库 | **寻寻** | |
| 安装目录 | `%LOCALAPPDATA%\企业知识库` | **`%LOCALAPPDATA%\寻寻`** | 由产品名决定 |
| 开始菜单 | `企业知识库\企业知识库` | **`寻寻`**（不再套一层文件夹） | |
| `identifier` | `com.enterprisekb.desktop` | 不改 | 外壳的窗口数据目录以它命名。从内部版 1.0.0 升级时，**旧对话记录**要从这里的 localStorage 迁到数据目录，改了就丢 |
| `mainBinaryName` | `EnterpriseKB` | 不改 | 进程名用户看不到，不值得冒险 |
| 数据目录、凭据管理器的服务名 | `EnterpriseKnowledgeBase` | 不改 | 索引库和 Key 都靠它 |

## 难点和做法

产品名一变，安装程序就认为这是另一个软件：新目录、新卸载项，旧的留在原地，用户会看到两个并排的程序。

`hooks.nsh` 在安装开始时查旧的安装记录：有的话静默运行旧卸载程序，再装新的。旧卸载程序只有勾选“删除应用数据”才会动数据，静默运行时不会勾；它也只删指向自己目录的快捷方式。

自动更新走的是 `/UPDATE` 模式，这个模式不创建快捷方式。旧快捷方式已被删除，所以钩子会补建开始菜单和桌面快捷方式。

用户要注意的一点：**固定到任务栏的图标会被取消**，要重新固定一次。

## 启用步骤

确认后：

```powershell
packaging\build_desktop.ps1 -Python .venv\Scripts\python.exe -Config packaging\rename\tauri.xunxun.conf.json
```

想永久改，就把 `tauri.xunxun.conf.json` 的内容并入 `tauri.conf.json`。改名之后所有版本都要带着这个钩子，否则还没升级的旧版用户跳版本时又会出现两个程序。同时要更新：`README.md` 的路径表、`desktop/README.md`、`project/config.py` 的 `app_name`、`desktop/src-tauri/Cargo.toml` 的 `description`。

## 测试结果（2026-11-05）

全部在隔离的目录里跑，用你的数据副本（124 个文件，3900 个片段）；你正在运行的寻寻和安装登记不受影响，结束后登记逐字节比对一致。

```bash
python packaging/test_upgrade.py --old <1.0.0> --new <寻寻 1.1.0> --data <副本> --work <短路径> --rename [--as-update]
```

| 场景 | 结果 |
|---|---|
| 1.0.0 → 1.1.0，同名升级 | 19/19 |
| 1.0.0 → 寻寻 1.1.0，手动安装 | 23/23 |
| 1.0.0 → 寻寻 1.1.0，按更新方式（`/UPDATE`） | 25/25 |

检查的内容：旧目录和旧卸载项消失，新卸载项出现，快捷方式补建；同一份数据上后台能启动，检查通过，升级前留了备份，文件和片段数不变；和干净安装相比没有多余或缺失的文件；卸载不删数据。

**没测到的：**

- 用安装向导点击的路径（默认“先卸载旧版”）。卸载和安装两半各自测过，连起来没有。
- 改名后的外壳窗口。同一个 `identifier` 只会唤起你正在运行的那个，要关掉寻寻才能试。改名不改外壳逻辑，风险小。启用时建议你自己装一次看看。
- 任务栏固定图标的实际表现。

## 自动更新的测试结果（2026-11-05）

外壳不能和运行中的寻寻并存，所以用单独身份的测试版（`com.xunxun.updatetest`）和一次性密钥，在本地起一个更新服务器，通过 WebView2 调试接口操作真实窗口。测试版和密钥都已删除。

| 流程 | 结果 |
|---|---|
| 从 1.0 升级来的用户只看到数据去向一页；关于页出现“检查更新”；提示 1.1.1 和更新说明；确认后下载、验签、关闭后台、安装、自动重启；重启后还在数据副本上，文件都在，引导不再出现 | 20/20 |
| 签名被篡改的更新被拒绝（The signature verification failed），程序继续运行；运行中恢复备份后 `restart_app` 自动重启，恢复已生效，只有一个实例 | 15/15 |
