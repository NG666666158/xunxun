# 公开发布前的开发记录

以下版本号是内部开发阶段使用的编号，不属于公开发行序列。原内部 1.4.0 的功能作为寻寻首个正式版本 **1.0.0（2026-11-10）** 发布。保留原始记录供追溯。

## [1.4.0] - 2026-11-10

### 新增

- 改名为“寻寻”，这是第一个公开发布的版本，安装包在 [GitHub Releases](https://github.com/NG666666158/xunxun/releases) 下载。安装包、开始菜单、安装目录和卸载项都叫“寻寻”。装过旧版“企业知识库”的，直接安装即可：安装程序会先卸载旧版，资料、对话和 Key 都保留；固定在任务栏的旧图标需要重新固定一次。
- 自动更新：设置 › 关于 › 检查更新。新版从 GitHub Releases 下载，验证签名后安装。
- 按文档类型找文件：“找一下我的简历”“有哪些合同”“把会议纪要列一下”能找到这一类文件，文件名和正文里没有“简历”“合同”这些字也能找到。入库后，后台会给每个文件写一张卡片，写明它是什么文件（类型、关于谁、一句话摘要）。只问类型时列出这一类的全部文件；说“最近的检测报告”时按时间从新到旧排。卡片在后台慢慢补齐，你提问时自动暂停，设为“只按文件名”的文件不读也不发送。
- 知识库的文件列表里，每个文件名下面会显示它的类型，点一下就能看到整张文件卡片（类型、关于谁、时间、摘要）。文件名本身写明了类型时，以文件名为准，卡片上会注明。“文件”标题旁边可以按类型筛选，每种类型后面带着文件数。

### 改进

- 资料里有相关内容、但没有问题问的那一年、那个地方或那个对象时，回答开头先说“资料里没有找到…”，再给出资料里有的内容，不再把相似对象的内容当成答案。公开评测上，该拒答时说出来的比例从 0.22 提高到 0.62（见 [docs/BENCHMARKS.md](docs/BENCHMARKS.md)）。
- 是 / 否题和二选一的题，回答会给出明确结论；问时间先后的题，证据会带上文件日期；引用会指到真正写着那个数字或名称的段落。公开评测上 260 道多文档题，23 题由错变对，没有题由对变错。

### 修复

- 找矛盾时按完整数字比较：“12” 不再算作 “12.5” 的一部分，“43214.85”“1.20亿” 这类长数字和带零的写法也能正确对上，少了一类误报的“说法不一致”。

### 数据去向

- 设置 › 数据去向的说明加上了“判断文件类型”：给文件写卡片时，文件名和正文开头约 900 字会发给对话模型。

## [1.3.0] - 2026-11-09

### 改进

- 一个问题问了几件事、答案分散在几份文件里时，找得更全：先保证几份不同的文件各有一段进入证据；哪个小问在找到的内容里还没着落，就单独为它再找一轮（只在需要时，平均多 0.1～0.4 秒）。公开评测上“所有出处都找到”的比例：多跳题 0.45 → 0.58，三篇来源的题 0.77 → 0.79。
- 问题里写了文件名（如“答辩PPT用了哪几步…”）时，先从这份文件里找答案，不再被内容相近的其他项目文件抢走。
- 追问（如“那它用了哪几步工艺？”）会接着用上一轮回答引用的文件，不再串到相似的项目里。
- “把答辩PPT总结一下”“合金粉末那份答辩PPT总结一下”“总结一下这份PPT”（刚找到或刚引用过的）都会通读整份文件来总结。
- 核对回答时遇到模型服务限流、超时或出错，最多再等 75 秒重试，不再跳过核对直接给出；实在等不到，就在本机核对回答里的数字和名称是否都出自原文，并在回答下方注明“只核对了数字和名称”。
- 问的词和资料里的词只差一点（如问“质保期”、资料写的是“保质期”）时，照样回答，但开头提醒资料里写的是哪个词，不再把两者当成一回事。
- 回答提到的地点、年份或名称在引用的资料里找不到时，开头提醒“可能讲的是别的对象”，请点开出处核对。
- 几份资料对同一件事写了不同的数字、日期或名称时，回答开头列出各自的说法和出处，不再只挑一个说。公开评测上被错误资料带偏的比例从 50% 降到 17%。

### 修复

- 不同文件夹里同名的文件（比如两个项目各有一份“04 答辩PPT.pptx”）不再被当成同一份文件的新旧版本而只留一份；回答里会标出各自所在的文件夹，分开说明。

## [1.2.0] - 2026-11-06

### 新增

- 不上传的文件：文件或文件夹可以设为“只按文件名”（能按名字、位置和时间找到，内容不读，也不发到硅基流动）或“不收录”，也可以按名字设规则。改设之前读过的文字会从索引和备份里清掉。在文件和文件夹旁的盾牌按钮里设，设置 › 数据去向下面能看到全部。

### 改进

- 首页重新设计：中间只有输入框和寻寻。
- 回答时不把文档里的文字当成指令。

- 回答更快：第一个字从约 8 s 提前到约 2 s，事实类问题从约 18 s 缩短到约 9 s，找文件和表格问题 1–2 s 内出结果（Qwen3-8B 实测）。
- 开着系统代理（如 Clash）时，访问硅基流动改为直连；直连不通时自动改走代理。也可以在 `preferences.json` 里用 `model_connection` 固定为 `proxy` 或 `direct`。
- 模型服务偶尔迟迟不回应时，8 秒后自动再发一次请求，用先回来的那个，不再干等 30 秒。
- 刚启动或刚输入问题时，提前建好到模型服务的连接。
- 回答后的追问建议在核对回答的同时就开始写。
- 核对回答时，照抄原文的句子不再交给模型逐句复核。
- 打招呼不再等模型。
- 读文件时如果账户余额不足，不再每隔几分钟重读一遍，等下次启动再试。
- 后台正在重新读取大文件（PPT、扫描件）时提问，不再先卡几秒到十几秒：检索和找文件不用等索引写完，读文件也会更快停下来让路。
- 导出诊断信息里多了每次回答各步骤的耗时，不含问题和回答的内容。

### 修复

- 问一份表格“一共多少条”时，只数了第一个工作表。现在问题没点名工作表时统计全部工作表，并逐表列出；点名了某个工作表时仍只数那一个。

## [1.1.0] - 2026-11-05

### 新增

- 首次打开时有引导：说明数据去向，获取并测试硅基流动 Key，选模型，添加第一个文件夹。从旧版本升级的用户只看一次数据去向。
- 设置里写明数据去向：文档文字、文件名和问题会发到硅基流动。
- 启动时检查索引库，损坏时不再打开它，并提供两条恢复路径：从备份恢复，或重新读一遍所有文件。
- 自动备份索引库：每天一份，升级后第一次启动前也备份一份，保留最近 3 份。
- 关于 › 导出诊断信息：日志和版本信息，不含 Key 和文档内容。
- 已具备应用内更新的能力，确定发布地址后开启。
- 支持 PowerPoint：能读 `.pptx`；旧版 `.ppt` 要本机装有 PowerPoint。预览用本机的 PowerPoint 转换，没装时显示近似版式。图片里的文字不读。
- 全文总结：“总结一下《X》”会通读整份文件，回答末尾写明读了多少，再问不用重读。很长的文件先说大约多久、多少钱，确认后才读。
- 表格问答：“这张表一共多少条”在本机按单元格计算，数字来自文件本身，并指出在哪些行。
- 对话记录和上下文存进数据目录，和索引库一起备份；重启后还能接着追问。旧版的对话会自动迁移过来，也不再只留最新 40 段。

### 改进

- 测试 Key 时会真正调用一次模型服务。之前余额不足也显示“可以用”，直到读文件才失败。
- 账户余额不足时明确提示，不再只说“问答服务暂时不可用”。
- 知识库页能看到全部文件：超过 500 个时可以显示更多，也可以按名字或位置搜索。读文件期间长列表不再频繁重绘。
- 多个文件同时读。扫描件不再挡住后面的小文件，读到哪页就能搜到哪页；有人提问时读文件会让路。
- 放宽文件大小：登记在原位的 PDF、Word、PPT、图片上限 1 GB，文本和 Excel 上限 50 MB。
- 找文件时写明一共多少个，也能只找图片。

### 移除

- 演示用的产品、部门和库存数据。问电话、价格这类问题不再答出演示数据，都去你的文件里找。

## [1.0.0] - 2026-10-28

第一个可安装的版本，自用。

- Windows 桌面客户端：监控文件夹和单个文件，文件留在原处，有变化自动跟上。
- 问答带引用，可打开原文定位；快捷键快速搜索；回答后的追问建议；首页“猜你想问”。
- 支持 PDF、Word、Excel、Markdown、文本和图片。
- 苹果风格界面和小狗寻寻。
